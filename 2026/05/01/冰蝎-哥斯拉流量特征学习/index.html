冰蝎/哥斯拉等Webshell木马流量特征学习

一：原理

Webshell（网站后门）是攻击者攻破 Web 应用后，在服务器 Web 目录下植入的一段可执行代码文件（PHP/JSP/ASPX/Python 等），通过 HTTP 请求触发执行系统命令、读写文件、反弹 shell 等操作

二：webshell 木马工具了解

中国菜刀（Chopper）：支持 PHP/JSP/ASPX/ASP，通信完全明文（仅 base64 编码参数值），无任何加密，流量特征最明显，是最早被安全设备检测的样本，现在很少使用。
蚁剑（AntSword）：支持 PHP/JSP/ASPX/ASP/Python/自定义，通信明文 base64（无加密），但功能强大、可自定义编码器（默认 base64 编码，可换 RSA/AES 等），目前活跃度高。
冰蝎（Behinder）：基于 Java ，v3/v4 支持 PHP/JSP/ASPX，核心特点是通信全程 AES-128-ECB 加密（密钥由连接密码派生），并伪造常见浏览器 UA 与 Content-Type，是”流量加密型” webshell 的代表，曾绕过大量安全设备。
哥斯拉（Godzilla）：支持 PHP/JSP/C#/Python/ColdFusion 等几乎所有语言，默认 AES-128-ECB 加密 + 伪随机加密，请求特征有独特的 UA 与 Cookie 签名。

一：中国菜刀（Chopper）

工作原理

菜刀客户端向服务器 webshell（如 chopper.php）发送 POST 请求，参数 cmd 中携带一段固定的 PHP 代码 @eval(base64_decode($_POST["z0"]));，实际执行的命令放在另一个参数 z0（base64 编码）里。webshell 收到后 eval 执行，把结果用 ->|输出|<- 的固定格式包住回传。全程零加密。

流量特征

1：URL 直指 webshell 文件：POST /chopper.php HTTP/1.1，特征就是根目录下不常见的 php/jsp 文件，浏览器正常访问路径不会有这种文件，正常业务不会对一个非预期的php文件发起高频请求
2：参数 cmd 明文可见：请求体中 cmd=%40eval%28base64_decode%28%24_POST%5B%22z0%22%5D%29%29%3B 即 cmd=@eval(base64_decode($_POST["z0"]));``http.request.uri contains "eval" 即可命中，菜刀大多数都是一句话木马
3：参数 z0 是 base64 编码的命令：解码 z0=QCRjPUBzaGVsbF9leGVj... 得到 @$c=@shell_exec("whoami");echo "->|".$c."|<-";
4：响应固定 ->| + 输出 + |<-：响应体第一眼就是 ->|xxx|<-，这个边界标记是菜刀的招牌特征，其他工具没有
5：UA 固定 IE 老版本：Mozilla/5.0 (compatible; MSIE 9.0; Windows NT 6.1; Trident/5.0)，现代浏览器不会用这种老 UA

三：冰蝎（Behinder）

工作原理

冰蝎是全程加密的 webshell 工具。请求时客户端用 AES-128-ECB 加密（密钥 = 连接密码 md5 后的前 16 位，默认密码 rebeyond 对应密钥 e45e329feb5d925b），将 eval|<php代码> 加密后 base64 编码放进请求体；webshell 端 openssl_decrypt 解密得到代码并 eval 执行。响应端先用 XOR 加密（encode() 函数）再回传。也就是说请求体是 base64(AES密文)、响应体是 XOR 密文，两者都不可读——这是冰蝎与菜刀/蚁剑的根本区别。

流量特征

1：请求体是 base64(AES-128-ECB 密文)：body 是一串 base64 字符（长度恰为 16 的倍数），完全不可读，没有任何 PHP 关键字、命令名，http contains "eval" 不命中——加密防护生效
2：Content-Type 固定 application/x-www-form-urlencoded：这是冰蝎 v3 的默认特征（服务端按表单解析其实它发的是裸 body），普通浏览器提交表单也常是这个值，属于”伪装正常但固定”的指纹
3：响应是 XOR 密文（不可读二进制）：响应 body 是乱码，无法直接看出命令输出；
4：UA 伪装常见浏览器：Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36... Chrome/107，伪装成正常 Chrome，但版本号可能偏旧
5：每次命令都是独立 POST：短连接、无心跳长连接，与 frp/nps 的长连接心跳完全不同；冰蝎是”请求-响应”式，符合正常 Web 访问的形态，隐蔽性主要靠加密本身，每执行一次命令，都会建立一条tcp短链接，用完就FIN关闭

6：冰蝎的请求头带有特征keep-alive

7:冰蝎伪装ua头是随机取得，如果看到对同一ip，ua头却在变化就有可能是冰蝎特征

8：3.0的jsp格式webshell请求头的Content-Type常见为Application/octet-stream

9：请求头特征和响应头特征，jsp的webshell请求时时会带上Pragma: no-cache，Cache-Control: no-cache，php格式则是响应头带上，响应头带connection：close

10：GET请求特征，每次连接会产生一个GET/pass=[xxxx]，且会生成16微随机密钥

四：哥斯拉（Godzilla）

工作原理

哥斯拉与冰蝎同为加密型 webshell，但协议更复杂、伪装更精细。请求时把要执行的代码先 base64 编码，再 AES-128-ECB 加密（密钥 = 密码 md5 前 16 位，默认 pass 对应密钥 1a1dc91c907325c6），最后 base64 编码放进参数 pass。响应格式是「md5(md5(pass))前16位 + base64(AES密文) + md5后16位」的三明治结构。哥斯拉自带 Java 客户端特征（真实工具就是 Java GUI），所以请求里会带 Java 相关的 UA 和 Cookie 签名。

流量特征

1：请求体：密文，URL 编码后 %2B 等符号明显，不可读
2：UA 固定 Java/1.8.0_xxx：哥斯拉是 Java 写的，默认 UA 是 Java/1.8.0_121 这类——浏览器不可能发这种 UA，http.user_agent contains "Java/" 直接命中，这是哥斯拉最强的硬特征（真实场景有经验的攻击者会改，但默认就是它）
3：Cookie 以分号结尾：Cookie: PHPSESSID=godzilla-labsession;——末尾多了一个分号，这是哥斯拉客户端自动生成的 Cookie 特征
4：响应三明治结构：35f504164d5a963d + base64密文 + 6a820e71614a4009——前面 16 位 + 后面 16 位是固定格式的 md5 校验段（md5(md5(pass)) 的前/后半），中间是 base64(AES密文)。看到「响应体前 16 字符像 hex、紧接大段 base64、再 16 字符 hex」就是哥斯拉
5：Accept 头特征：Accept: text/html, image/gif, image/jpeg, *; q=.2, */*; q=.2——Java 默认的 Accept，和浏览器不同

6：在默认编码情况下：jsp的shell会出现xc，pass，getClass().getClassLoader()等字符

7：第一个请求包通常比后两条更大更大且返回包是空的
