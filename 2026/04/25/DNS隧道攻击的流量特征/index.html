dns隧道攻击学习

一：原理

dns隧道攻击是高级的红队渗透技术，攻击者利用大多数企业的业务需要进行漏洞攻击，大多数企业为了满足业务需求不会对udp53端口进行waf检测和拦截，内部终端需要满足业务利用udp53端口进行出站去请求其他业务站点

二：dns隧道攻击工具了解

现在主流的三个工具，iodine，dnscat2，dns2tcp，各自的特征

iodine是ip报文封装型工具，作用就是搭建隧道，将ipv4报文封装在dns流量中，客户端机器也就是受害者会多出一张虚拟网卡(层3网卡)，默认使用NULL记录传输载荷

dnscat2是c2远控信道型，建立加密的双向命令和控制信道，支持文件上传，命令执行，主要用于APT攻击，长期驻留受害者机器，偷取数据，默认使用TXT记录，握手阶段携带固定dnscat特征字符串，流量加密

dns2tcp是tcp流量转发型，将tcp流量封装在DNS流量中，仅支持TXT/Key记录，默认使用TXT记录，base64编码，保持0.6s心跳间隔

三：三种工具在数据包中的流量特征(结合实际攻击数据包学习放在最后面)

一：iodine

iodine的工作步骤：

1：服务端vps启动iodined程序，监听53udp端口，等待受害者的dns解析请求

2：客户但运行iodine程序，将需要外带的ipv4报文分段编码为超长子域名

3：流量封装在dns流量中，发送到企业的内部dns解析服务器

4：内部dns服务器将流量转发到攻击者的权威dns服务器，服务端解码报文，得到数据，后续可通过将响应数据封装在NUll记录中回传给客户端，实现双向通信

wieshark抓包分析

iodine工具有四个无法绕过的专属特征

1：iodine工具流量的一个特征，dns查询包中包含tunnel字符串，使用dns.qry.name contains “tunnel”筛选

2：iodine默认使用dns NULL记录传输载荷，NULL记录对应的类型编号为10，这个是iodine的主要特征，使用dns.qry.type==10

3: iodine的ipv报文载核默认使用base32编码，编码后dns流量中的超长子域名仅包含0-9，a-z等字符

4：因为携带载核，iodine的通信流量的子域名长度远超正常业务的几十字节范围，可以过滤长度异常的流量 dns.qry.name.len > 100

二：dnscat2

dnscat2的攻击步骤

1：服务端启动dnscat2.rb，绑定权威dns服务器，设置共享密钥，穷的那个监听

2：客户端执行攻击者上传的恶意程序，可能是powershell或者c语言等编写的，将需要传输的数据加密以子域名部分传出

3：首次通信时，客户端与服务端握手，默认会留下一个带固定字符串dnscat的流量包，但是攻击者可以修改源码改掉，所以不是很实用，后续会将加密密钥，会话信息编码在特殊子域名中，完成验证

4：后续客户端将数据等载核封装在TXT字段的dns查询中，服务端将响应报文封装在TXT字段的dns查询请求中，以此实现双向通信

流量特征

1：最关键的特征，dnscat2使用TXT字段传输载荷，占比百分之80以上，正常业务占比也就3左右，过滤dns.qry.type==16

2：编码特征，dnscat2采用base32编码，只要A_Z,2-7等字符，dnscat2会将超长子域名分段，使得其和正常dns查询长度差不多

3：握手阶段的特征包带dnscat字段,dns.qry.name contains “dnscat”

4: 请求大，响应小，正常的dns业务是请求小，响应大

数据包分析

dns.qry.type==16

三：dns2tcp

dns2tcp的步骤

1：服务端运行dns2tcpd程序，配置转发端口，权威dns服务器等配置，开启udp53端口监听

2：客户端运行dns2tcpc程序，与服务端建立连接

3：客户端将需要转发的流量封装在dns查询请求的子域名中，客户端的业务转发dns服务器指向攻击者的权威服务器，权威服务器将数据转发到攻击者指定的端口

dns2tcp的流量特征

1：dns.qry.name contains “dns2tcp”

2:dns2tcp使用TXT和KEY字段传输载荷，默认使用TXT，这两种在正常业务中占比都很低，如果某一种占比很高且无合理解释大概率就是dns2tcp流量

3：dns2tcp的流量只要编码，无加密特征，且会以0.6-3s的频率发送保活包，也可以利用此区分

数据包分析

dns.qry.name contains “dns2tcp”

dns.qry.type==16
